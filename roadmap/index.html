Learning in public · 2026 onward

Applied AI labs.
Evidence over hype.

Three focused projects I plan to develop as public, reproducible proof of AI engineering. Each should go beyond a notebook: data, tests, measurable evaluations, operations and a working demo. These are proposed projects, not completed deliveries.

LAB 01 / PLANNED · Highest priority

RAG Evaluation Studio

Build a grounded question-answering service over a consent-safe document collection. Compare retrieval approaches, show citations and fail honestly when evidence is missing.

PythonRAGHybrid retrievalEvaluation
Ingest + chunk→Retrieve + rerank→Answer + cite→Evaluate

Acceptance criteria: a reproducible labelled question set; recall@k and citation correctness; explicit unanswerable-question cases; response latency and token-cost accounting; injection-resilience tests.

Artifacts to publish: code, Docker setup, example dataset with safe licence, evaluation dashboard, error analysis, architecture decision records, demo and CI tests.

LAB 02 / PLANNED

Production ML Pipeline

A small end-to-end prediction service built to demonstrate the full ML lifecycle rather than a single accuracy score. Choose an open dataset with a defensible baseline.

PythonFeature engineeringMLflowServing
Data quality→Train + validate→Serve + monitor

Acceptance criteria: time-aware train/test split where appropriate; baseline comparison; leakage checks; calibration, segment-level metrics, drift signals and model card.

Artifacts to publish: experiment tracking, reproducible pipeline, endpoint, integration tests, observability notes and inference-cost estimate.

LAB 03 / PLANNED

Forward Deployed AI Workflow

Choose a realistic customer workflow, define a measurable business outcome, prototype the smallest reliable agent/tool system and document the deployment trade-offs.

Tool callingHuman approvalReliabilityIntegration
Discovery brief→Tool workflow→Sandbox execution→Review

Acceptance criteria: input/output contracts, scoped permissions, destructive-action approval, deterministic test cases, tracing, rollback strategy and a customer-oriented demo.

Artifacts to publish: anonymized solution brief, architecture, tests, product demo, evaluation report and operational runbook.

How this becomes a credible portfolio

Every public project should show: what was built, why each choice was made, what failed, which metrics were measured and how someone else can run it. Private prototypes stay private; the case study can still communicate the engineering.
