Databricks · AI/BI · Analytics

Retail Churn Copilot

Bring the analytics conversation closer to the customer on a Databricks-native stack.

Private source · prototypeEngineering case study

01 / The problem

A business analyst wants an approachable answer to a retention question. Raw queries and warehouse schemas are not the right interface for every stakeholder.

02 / Engineering approach

  • A Databricks application structure with AppKit analytics and Genie plugins.
  • A React client and an Express server handling user interaction and requests.
  • Databricks SQL warehouse execution as the data retrieval layer.
  • Bundle-based deployment configuration to package the application.
User question→Genie / SQL→Business insight

Documented stack: Databricks Apps · AppKit · Genie · Databricks SQL · TypeScript · React · Express

03 / Why this matters for FDE / AI Engineering

A Forward Deployed Engineer can connect enterprise data to a concrete frontline question, while preserving semantic context, access controls and debuggability.

04 / What is demonstrated — and what isn't

Private TypeScript repository contains client, server, Databricks configuration and lint/typecheck tooling.

The README documents an AppKit-powered application and development/deployment commands. It does not establish validated churn-model accuracy, a production customer deployment or a measured retention gain.

05 / How I would validate it

  • Create a traceable question-to-query-to-result flow with realistic synthetic data.
  • Validate ambiguous questions, row-level permissions and sensitive outputs.
  • Define usefulness measures with business stakeholders and compare with a SQL-only baseline.

These are evaluation and hardening steps, not claims that each has already been completed.
