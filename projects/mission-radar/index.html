Mission Radar

A personal data-and-workflow application for discovering, classifying and following up relevant opportunities.

Private source · evolving personal applicationEngineering case study

01 / The problem

Recruitment opportunities arrive from fragmented platforms and conversations. Without a single pipeline, deduplication, recruiter follow-ups and prioritization become hard to track.

02 / Engineering approach

  • Data-oriented dashboard with mission status and contact/recruiter workflows.
  • Source enrichment from LinkedIn through explicit Apify-backed interaction.
  • Session protections and server-side secrets rather than browser-visible keys.
  • Documented tests and deployment mechanics for a private working application.
Sources→Enrich + prioritize→Follow-up dashboard

Documented stack: Next.js · TypeScript · Notion API (repo version) · Apify · Netlify · Test tooling

03 / Why this matters for FDE / AI Engineering

Demonstrates pragmatic engineering across heterogeneous APIs, source quality, user workflows and safety boundaries rather than just a model prompt.

04 / What is demonstrated — and what isn't

Private repository with Next.js app, API helpers, tests and deployment configuration.

The inspected repository README describes the Notion-backed iteration. Later architectural ideas are not presented here as already implemented in this repository.

05 / How I would validate it

  • Check deduplication quality on intentionally varied listings.
  • Track freshness and source attribution; never invent missing details.
  • Test reconciliation and state transitions before automating notifications.

These are evaluation and hardening steps, not claims that each has already been completed.
