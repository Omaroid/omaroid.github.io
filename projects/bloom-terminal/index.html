BLOOM Terminal

A Databricks-first intelligence workspace that turns public data and cloud updates into a focused, project-aware research feed.

Private source · public demoEngineering case studyOpen live demo ↗

01 / The problem

Engineers need to follow rapidly changing product capabilities without drowning in unfocused release notes and articles.

02 / Engineering approach

  • Publisher feeds ingested and organised by topic, provider and relevance.
  • A watchlist connecting research to active projects and priorities.
  • Saved research notes, historical snapshots and an actionable briefing layer.
  • A Netlify Function serves the public feed API, while the production build publishes only the browser assets.
Publisher feeds→Watchlist + briefing→Research notes

Documented stack: Node.js · Browser UI · Publisher feeds · Netlify Functions · GitHub Actions

03 / Why this matters for FDE / AI Engineering

Relevant to FDE because keeping solutions current is an evidence, prioritisation and documentation problem, not merely a search problem.

04 / What is demonstrated — and what isn't

Private source repository with tests, public publisher feeds, a local server and Netlify deployment configuration.

The repository documents deterministic relevance matching, not a verified generative-AI research agent. Source interpretation must always be checked against linked publisher information.

05 / How I would validate it

  • Measure feed deduplication and false-positive relevance matches.
  • Handle stale, undated and disappearing source content explicitly.
  • Test accessibility, permission boundaries and degraded-source behavior.

These are evaluation and hardening steps, not claims that each has already been completed.
