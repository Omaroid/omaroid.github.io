Computer vision · Mobile-first product

PokéValue

An applied-vision product that ties visual identification to a useful market workflow.

Private code · public application linkEngineering case study

01 / The problem

A collector wants to identify a physical card accurately and understand its value in context, rather than manually searching several catalogues and price sources.

02 / Engineering approach

  • Image-based card identification when a model key is available, with an OCR fallback path.
  • Entity matching across editions, language, condition and card variants.
  • Market-pricing sources and portfolio snapshots separated from identification.
  • Mobile-first batch scan and collection management workflows.
Camera / image→Recognition + identity→Pricing + collection

Documented stack: Next.js · TypeScript · Vision model / OCR fallback · Market data · Vercel

03 / Why this matters for FDE / AI Engineering

Shows how vision AI becomes a complete user-facing product through entity resolution, fallbacks, pricing provenance and persistent state.

04 / What is demonstrated — and what isn't

Private Next.js repository with a deployment URL listed in GitHub metadata.

The repository contains extensive implementation documentation. The public application URL comes from the repository metadata; its uptime, accuracy and current data availability are not guaranteed.

05 / How I would validate it

  • Build a representative labelled image evaluation set for recognition.
  • Quantify ambiguity across language and edition variants.
  • Document confidence thresholds and user correction loops.

These are evaluation and hardening steps, not claims that each has already been completed.
