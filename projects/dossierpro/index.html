DossierPro

AI-powered candidate intelligence, from messy source documents to usable workflows.

Private code · implementation described in READMEEngineering case study

01 / The problem

Recruitment teams need to convert inconsistent CVs, LinkedIn profiles and client needs into structured candidate profiles and tailored competency dossiers. The user journey matters as much as the model output.

02 / Engineering approach

  • Asynchronous candidate ingestion from CVs and LinkedIn, with a separable enrichment workflow.
  • Structured candidate and client records; candidate-to-role matching and dossier generation.
  • Long-running jobs and progress reporting using Redis-backed infrastructure and server events.
  • Document outputs, sharing workflows and quota/billing boundaries as part of the product.
CV / profile→Extraction + matching→Dossier / workflow

Documented stack: Next.js · TypeScript · PostgreSQL / Prisma · OpenAI · Redis · Supabase · Apify

03 / Why this matters for FDE / AI Engineering

Forward Deployed work combines user discovery, secure enterprise data flows, model-assisted automation and a usable product. This is the closest portfolio case to that full cycle.

04 / What is demonstrated — and what isn't

A private implementation with extensive project documentation; no public code or company data exposed.

The private repository's README describes these capabilities. Production usage, matching accuracy, latency and customer impact are not independently verified. Some integrations require credentials and service access.

05 / How I would validate it

  • Evaluate extraction accuracy on consented, representative resumes.
  • Measure matching consistency, fallback behavior and unsupported assertions.
  • Exercise job retries, idempotency and privacy safeguards before wider deployment.

These are evaluation and hardening steps, not claims that each has already been completed.
